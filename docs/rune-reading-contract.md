# Proposed reading contract (v0 draft)

A shared adapter should normalize existing routes to an envelope such as `{reading_id, mode, source, delivery, status, provenance, payload}`. `mode`: `pouch` or `sticks`; `source`: `ibm_qpu` or `synthetic_demo`; `delivery`: `precomputed`, `live`, `demo`; `status`: `queued`, `running`, `ready`, `failed`, `recoverable` as applicable. These are proposed, not existing endpoints. Use stable reading IDs and version fields. `ready` with zero recognized runes is a success. Do not include secret IBM credentials or unallocated inventory in public payloads.

## Pouch payload
`draws`: ordered objects `{position, rune_id, name, glyph}`. `position` past/present/future. IDs 0–23 correspond to `rune_catalog.json`. Private audit stores raw ranks/shot/validity and job/hash; optional public provenance can expose non-sensitive version/backend. Example `fixtures/pouch_demo.json`.

## Sticks payload
`casting`: `{point_count:256, slots:72, chords:[{sequence, endpoint_a, endpoint_b, ...}]}`. Optional `p1,p2` are Cartesian unit-circle coordinates, `degenerate` identifies zero length. Chord sequence is 1-based, frame step counts slots 0..72; endpoint indices 0..255. `P(k)=(cos(2*pi*k/256), sin(2*pi*k/256))`. Segment `{stick,t_start,t_end}` has `0 <= t_start < t_end <= 1`; find chord by sequence; interpolate `P(t) = A+t*(B-A)` using original endpoint order, not sorted endpoints. In SVG with center (cx,cy), radius R, use `(cx+R*x, cy-R*y)`. Do not snap or extend segments.

`timeline`: subset of V0.10 `build_reading_timeline` output with `{profile_sha256, casting_size, candidates, frames, events, first_shown, final}`. `candidates` maps ID to `{id,rune,glyph,first_appearance,score,segments,...}`. `frames` maps string step to `{shown, compounds}`; `shown` maps rune name to `{rune,glyph,primary_id,primary_step,occurrence_count,occurrence_ids,earliest_surviving,size,quality,presentation_rank}`. Private full frames may also contain `statuses` mapping ID to `{status,parent_ids}`. Public timeline can omit rejected candidates/statuses, but retain every ID referenced by frames/compounds/events. `final` equals frame 72. Events record `emerged`, `reappeared`, `embedded`, `withdrawn`, `primary_changed`, `count_changed`. A compound relation records rune names, candidate IDs, supporting sticks, overlap and formation_step. `first_shown` is historical, not necessarily equal to final earliest surviving. `occurrence_count` includes primary; near duplicates not counted again; embedded separate.

See `fixtures/sticks_demo.json` for a constructed UI demonstration. It is deliberately not a complete RC1 analysis; it uses a hand-selected constructed geometry and earlier recognizer, with no profile hash. For integration testing use the included actual RC1 synthetic fixtures `fixtures/sticks_rc1_seed_*.json`. The recognition package exposes `analyze_casting` and `public_timeline`; the latter already implements the public projection described here.
