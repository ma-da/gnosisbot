# Security and release policy

This is research alpha, not a security-certified production system. Report vulnerabilities privately to the repository maintainer through the contact page; do not publicly post credentials, user data or unrevealed outcomes. There is no promise of a response SLA.

- HTTPS, exact allowed Origin, HTTP-only secure session cookie, owner and admin authorization. Retain existing key identity. Public API never requires an account private key. Browser operations and third-party resources need review; use a browser CSP compatible with the current inline SVG/scripts and CDN dependencies before unrestricted public access.
- Keep secret env, IBM SDK settings, database, user keys, tokens, raw commercial results, GQTP nonces/signing key, contact encryption key and research exports outside the repository. `.gitignore` is defense in depth, not a secret scanner. Do not use `git add -f` for ignored private material. Run a proper secret scanner and review Git history/staged paths. Rotate any previously exposed credential; if a GQTP signing key is compromised, plan an explicit documented key transition, not silent replacement. Avoid printing request cookies.
- API binds loopback only; proxy terminates HTTPS, forwards only expected requests, does not cache authenticated or deep-linked readings, and honors response headers. Avoid public access to Uvicorn, private state, or the repository directory. Admin disabled by default; prefer VPN or restricted access when enabling. `noindex` is not an access-control mechanism.
- Independent worker and explicit authorization gates prevent routine HTTP use from creating new paid jobs. Admin trials, automatic submission, sandbox and trial email disabled by startup guard. External provider limits and credit/cooldown checks are not comprehensive DDoS/abuse prevention. Add edge rate limiting, registration abuse control, health monitoring, incident response, legal/privacy review and backup/restore drills before broad launch.
- Public source only contains the historical demo and labeled synthetic fixtures; physical stock, private accounts and restricted research exports are excluded. A public GitHub repository also requires asset and corpus redistribution review (see LICENSING.md).
